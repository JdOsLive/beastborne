Online — motion & interaction spec

The nine online cards spec layout; this card specs how the page moves. One cursor in two costumes, one payload grammar, every transition named with a duration, and a hard ambient budget. Doctrine: FLOW / ALIVE / SNAP — player input is always the sharpest motion on screen. Where a mock disagrees with this card on motion, this card wins.

1 · The cursor — one organism, two costumes

The clearance rule (the page-wide ruling the mocks never made): the traveling violet RING (concentric +10px gap, 4px border) needs ≥12px of clear space on every side of its host. Hosts with that clearance are RING HOSTS. Anything tighter — dense rows and slips inside scroll containers — wears the slab cursor instead: the SAME cursor rendered as a border recolor (#9b6cff) + kbLand flash + fill lift, border/bg only (scroll-grid law). Cursor identity never forks; only the costume does.

4 · Ambient life budget — three living things, nothing else

The hub's living elements are exactly three — one per doctrine layer. Anything else that moves must be a ≤150ms answer to player input or a one-shot data-change ack.

  • ALIVE — the violet ring. The one perpetually-waving thing. Ink-lean multi-sine, imperative, root-level.
  • FLOW — the wave header. Shipped BbHeaderWaves mounted first-child in the chrome band, Accent="blue" → assets Assets/ui/wave-blue-a.png (1600×70 tile · layer A · 30s period ≈53px/s leftward · opacity .09 · strip h58) + Assets/ui/wave-blue-b.png (1600×53 · layer B · 18s ≈89px/s rightward · opacity .14 · strip h35). Imperative per-tick integer translateX, native-size tiling, modulo wrap (seam laws). Host paints NO background — .bhw-base owns the opaque band fill. Both PNGs are baked and in-repo — do not re-bake, do not miss them in the build.
  • FLOW — the ticker crawl. 90px/s imperative loop + the LIVE cap's 1.6s pulse dot (the page's ONLY pulsing dot). Not yet shipped — no band is reserved; it carves its own 60px when it lands.
  • State-scoped: queue pulse rings exist only while Searching — they are the queue's voice, not page ambience.
  • Input-answer motion (outside the budget): the Smash pop — the ≤180ms transition on ring-host GLYPHS plus the hover-gated hubSmashWiggle loop (0.7s, runs only while a glyph is hovered / kb-lit, VERIFY LIVE). Labels never move. It never idles, so it costs no ambient headroom. Also the BbIconScroll glyph drift on the root — house-standard on every tab, not counted as an Online living thing.

Explicitly does NOT animate: presence green dots (static — the crawl cap owns the pulse) · the QUICKPLAY tile SURFACE (no sheen — the 4.8s sweep stays PLAY's signature; only its ghost glyph + label pop on input) · goal/XP bars (0.2s imperative-pixel fill on data change only) · rank diamonds (except queue pulse + rank-up recolor) · TOP/HEADLINER stamps inside scroll rows (stay tilted at −3° — the straighten-on-hover grammar is suspended where transform changes are illegal, finding №9) · empty seats · zone borders · crawl separators · leaderboard deltas (one 0.2s blink on data change, no loop). No colored glows anywhere (no-glow law). Surfaces are solid; only the ring is liquid.
